## 1. 性能与瓶颈（最该背的一组）

| 英文 | 中文 | 一句话 |
|---|---|---|
| **Arithmetic intensity** | 算术强度 | $\text{ops}/\text{bytes}$，算法的属性 |
| **Ops:byte ratio** | 机器平衡点 / ridge | $\text{Peak FLOPS}/\text{Bandwidth}$，**硬件的属性** |
| **Roofline** | 屋顶线模型 | 对角线是带宽上限、水平线是算力上限，交点是 ridge |
| **Compute bound** | 算力受限 | $I > I_{ridge}$，加带宽没用 |
| **Memory bound** | 带宽受限 | $I < I_{ridge}$，**加算力没用** |
| **Prefill** | 预填充 | 处理输入序列、建 KV cache，**算力受限，决定 TTFT** |
| **Decode** | 解码 | 逐 token 自回归生成，**带宽受限，决定 TPS** |
| **TTFT** | 首 token 时间 | Time To First Token |
| **TPS** | 每秒 token 数 | ⚠️ 有歧义：单用户延迟 or 服务吞吐 |
| **Perceived TPS** | 感知 TPS | 首 token 之后单用户观察到的速率（**延迟**） |
| **Total TPS** | 总 TPS | 整个服务每秒生成的总 token（**吞吐**） |
| **ITL / TPOT** | token 间隔 | Inter-Token Latency；**10ms ≈ 100 token/s** |
| **TTFB** | 首字节时间 | **语音合成版的 TTFT** |
| **RTF** | 实时因子 | $t_{\text{处理}}/t_{\text{音频}}$；**你的锚点：GX8006 ≈ 0.044** |
| **Latency percentiles** | 延迟百分位 | **P50/P90/P95/P99——别用均值** |

> **对照**：[技术名词表 11.2 / 11.3](../技术名词表.md)。你这张表已经有了，本课补的是**怎么用它们做判断**。

## 2. 模型与架构

| 英文 | 中文 | 一句话 |
|---|---|---|
| **Autoregressive token generation** | 自回归 token 生成 | LLM/VLM/ASR/TTS 的原型 |
| **Iterative denoising** | 迭代去噪 | 图像/视频生成的原型 |
| **Causal LM** | 因果语言模型 | 基于此前 token 预测下一个；**所有生成式 LLM 都是** |
| **Encoder / Decoder** | 编码器 / 解码器 | 造内部表示 / 用内部表示产出 |
| **Encoder-decoder** | 编解码结构 | Whisper 用的；LLM 是 decoder-only |
| **Embedding layer** | 嵌入层 | 输入层，token → 向量 |
| **LMHead** | 语言模型头 | 输出层，隐藏状态 → logits |
| **Transformer block** | Transformer 块 | attention + FFN + normalization |
| **Attention** | 注意力 | 靠 Q/K/V 关联 token；**是推理最贵的部分** |
| **Self / Cross attention** | 自 / 交叉注意力 | 同一序列 / Q 来自另一序列（图像对文本） |
| **Multi-head** | 多头 | 每头一次独立 attention，可能各管一类关系 |
| **KV cache** | KV 缓存 | **prefill 建、decode 用、占显存、可复用、要传、需量化** |
| **PagedAttention** | 分页注意力 | KV cache 分页 + 查找表，**允许碎片化存储** |
| **Sliding window attention** | 滑窗注意力 | $O(N^2) \to O(Nw)$，w 常 8K-32K |
| **MoE** | 专家混合 | 线性层加稀疏性；router 每层为每个 token 选少数专家 |
| **Expert** | 专家 | MoE 里的小矩阵 |
| **Dense model** | 稠密模型 | 对比 MoE；**32B 以下更划算** |
| **Latent space** | 潜空间 | 图像/视频的低维表示（约像素值的 1%） |
| **VAE** | 变分自编码器 | latent → 像素 |
| **CFG / guidance scale** | 无分类器引导 | 每步跑两次前向（有/无条件），按此合并 |
| **Denoising step** | 去噪步 | 图像 30-50 步，视频约 50 步 |
| **Few-step model** | 少步模型 | ≤8 步出图，**快 80-90% 但质量明显降** |
| **Distillation** | 蒸馏 | 学 teacher 的**概率分布**而非仅答案 |
| **LoRA** | 低秩适配 | **改行为不改架构** |

## 3. 数字格式与量化

| 英文 | 中文 | 一句话 |
|---|---|---|
| **Dynamic range** | 动态范围 | 最小值到最大值的跨度；**浮点靠指数位赢整数** |
| **Granularity** | 粒度 | **多少个值共享一个 scale factor** |
| **Scale factor** | 缩放因子 | 从低精度映射回高精度的乘数 |
| **Mantissa / Exponent** | 尾数 / 指数 | 浮点三段之二；**指数买动态范围** |
| **FP8 / E4M3** | 8 位浮点 | 4 位指数 + 3 位尾数 + 1 符号；**Hopper 引入** |
| **MXFP8 / MXFP4** | 微缩放格式 | **block = 32** 的块级 scale；**Blackwell** |
| **NVFP4** | NVIDIA FP4 | **block = 16 + 二级全局 scale**；专有 |
| **Microscaling** | 微缩放 | 块级 scale 的做法名 |
| **QAT** | 量化感知训练 | 权重和 scale 一起训 |
| **PTQ** | 训练后量化 | **开放模型只能做这个** |
| **Calibration** | 校准 | PTQ 里用来保精度（如 KL 选截断阈值） |
| **Perplexity** | 困惑度 | 给模型期望序列算似然；**量化后看增幅最小** |
| **GGUF** | — | 本地分发高度量化模型的格式 |
| **AWQ / GPTQ / SmoothQuant** | — | 三种知名的 PTQ 权重量化方法 |

> **对照**：[Lesson 21](../lesson-21-量化原理与误差分析/)（公式侧）+ [Lesson 22 实验C](../lesson-22-MNN算子实现与量化部署/实验C_int8推理解剖.md)（MNN 的 int8 实现）。
> **本课补的是格式侧**：为什么有 block level、为什么生产用浮点而不用整数。

## 4. 推理优化技术

| 英文 | 中文 | 一句话 |
|---|---|---|
| **Batching** | 批处理 | 并行跑多请求；**提升吞吐，不降单请求延迟** |
| **Static / Dynamic / Continuous batching** | 静/动态/连续批处理 | 等满 / 等满或超时 / **token 级换入** |
| **In-flight batching** | 飞行中批处理 | TensorRT-LLM 对 continuous batching 的叫法 |
| **Prefix caching** | 前缀缓存 | 跨请求复用 KV cache；**前缀在首个不重复 token 处结束** |
| **Cache-aware routing** | 缓存感知路由 | 把请求导向已有匹配前缀的副本 |
| **KV cache offloading** | KV 卸载 | 往 G2/G3/G4 层级下放 |
| **Speculative decoding** | 投机解码 | 草稿 → 验证 → 接受；**只改善 TPS 不改善 TTFT** |
| **Acceptance rate** | 接受率 | 草稿被接受的比例；**一个被拒，其后全废** |
| **Draft / Target model** | 草稿 / 目标模型 | 草稿应至少小 10 倍 |
| **Medusa** | — | 嫁接 2-4 个额外解码头 |
| **EAGLE** | — | 吃三处隐藏状态，可出 8 个草稿，**通用首选** |
| **N-gram speculation** | N-gram 投机 | **无草稿模型**，靠字典；**代码补全强于 EAGLE** |
| **Lookahead decoding** | 前瞻解码 | 推理时生成 n-gram 填字典，更通用但更费算力 |
| **Chunked prefill** | 分块预填充 | 长输入切块与 decode 交错 |
| **Disaggregation** | 拆解 | prefill 与 decode 分到独立引擎 |
| **Conditional disaggregation** | 条件式拆解 | 先让 decode 引擎判断能否本地处理 |
| **xPyD** | — | 5P3D = 5 个 prefill + 3 个 decode |
| **PP / TP / EP / CP** | 流水/张量/专家/上下文并行 | PP 仅多节点；**TP 低延迟**；**EP 高吞吐**；**CP 视频专用** |
| **Expert router** | 专家路由 | 决定 token 激活哪些专家；**小且被复制到每卡** |
| **Topology-aware parallelism** | 拓扑感知并行 | 按 NVLink/IB 的带宽差设计并行策略 |

## 6. 硬件

| 英文 | 中文 | 一句话 |
|---|---|---|
| **SM** | 流多处理器 | **内含多个 core** |
| **CUDA Core / Tensor Core / SFU** | — | 标量 / **矩阵（MMA，推理基础）** / 特殊函数（softmax 要） |
| **MMA** | 矩阵乘累加 | $D = A \times B + C$，推理的原子操作 |
| **Dense vs Sparse FLOPS** | — | 稀疏指 2:4 结构化；**默认推理是 dense** |
| **VRAM / HBM** | — | 显存；HBM3/3e/4 各代 |
| **DRAM vs SRAM** | — | 片外通用 / **片上快而小** |
| **L0 / L1 / L2** | — | 指令缓存 / **每 SM 共享内存** / 跨 SM 全局；H100：256KB/SM、50MB L2 |
| **NVLink / NVSwitch** | — | 卡间一对一（**Hopper 900 GB/s、Blackwell 1800 GB/s**）/ 节点内全互联 |
| **InfiniBand** | — | 节点间（400 Gb/s per NIC；**以太网只 100**）|
| **MIG** | 多实例 GPU | 切成最多 **7** 片；**7 因为 SM 数不是 2 的幂** |
| **Grace / Vera CPU** | — | 价值在 **CPU-GPU 互联 900 GB/s**（卸载 LoRA/KV cache）|
| **G1–G4** | — | KV cache 四级存储：**VRAM → CPU RAM → 本地 SSD → 网络存储** |
| **Hopper / Ada / Blackwell / Rubin** | — | FP8 / 图形向无 NVLink / **FP4+微缩放** / HBM4 + **CPX** |
| **CPX** | — | Rubin 时代**专做 prefill** 的独立芯片 |

### 8.3 我给你的筛选建议

**按你的方向，优先级排序**：

| 优先级 | 读什么 | 为什么 |
|---|---|---|
| 🔴 **立刻** | FlashAttention 论文（**只看 1 的 §2-3**） | 把 [03](03_模型机制与瓶颈计算.md) 的 roofline 和融合打通，**这是你短板 3 的最短路径** |
| 🔴 **立刻** | GPTQ 或 AWQ（选一篇读透） | 补短板 1；**读的时候对照 [06](06_量化_动态范围与粒度.md) 的动态范围/粒度两条线** |
| 🟡 **接着** | PagedAttention（vLLM 论文） | 理解 KV cache 管理这个核心概念 |
| 🟡 **接着** | Modal 的 GPU Glossary | 硬件术语扫盲，**比读 spec sheet 高效** |
| 🟢 有空 | EAGLE / Mamba / DiT | 扩展视野，了解前沿方向 |
| ⚪ 需要时 | DDIA / SRE / K8s 文档 | 第 9 章方向，**你暂时用不到** |

> 💡 **一个读论文的方法建议**：**读这些论文时，始终问"它是在 ridge 的哪一侧做的优化"**——
> - FlashAttention 砍 $N^2$ 流量 → **提高 $I$**（从带宽受限翻向算力受限）
> - GPTQ/AWQ 降位宽 → **同时缓解两侧**（字节减半 + 低精度算力翻倍）
> - PagedAttention 减少碎片与重复 → **减少有效 Bytes**
> - EAGLE 用闲置算力换 token → **利用"算力在 decode 时闲置"这个事实**
>
> **有了这一个框架，这些论文读起来会快得多**，而且你会看出它们之间不是孤立技巧。

### 你从这一课应该带走的三样东西

1. **一个判断流程**：算算术强度 → 比机器平衡点 → 决定优化搬运还是优化 kernel
2. **一套量化语言**：dynamic range（为什么浮点）+ granularity（block 为什么存在）+ 敏感度排序
3. **一个可迁移的视角**：**边缘的 tiling/复用 ↔ 云侧的融合/缓存 ↔ 编译器的调度，本质都在解决"让数据少搬一次"**
