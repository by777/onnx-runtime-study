# 量化示例：浮点数 → uint8 → 定标

## 场景

浮点数 `[0.1, 0.9]` 量化到 uint8（非对称），最终转成硬件友好的定标（multiplier + shift）形式。

---

## Step 1：算 scale

```python
x = [0.1, 0.9]
x_min, x_max = 0.1, 0.9
q_min, q_max = 0, 255          # uint8 范围

scale = (x_max - x_min) / (q_max - q_min)
      = (0.9 - 0.1) / 255
      = 0.8 / 255
      = 0.0031373
```

**scale = 0.0031373**：每个整数阶梯代表 0.0031373 的实数。

---

## Step 2：算 zero_point

```python
zero_point = round(q_min - x_min / scale)
           = round(0 - 0.1 / 0.0031373)
           = round(0 - 31.875)
           = round(-31.875)
           = -32
```

**zero_point = -32**：实数 0 映射到整数 -32（计算中间值，最终 clamp 到 [0,255]）。

---

## Step 3：量化 q = round(x/scale) + zero_point

```python
# x = 0.1:
q = round(0.1 / 0.0031373) + (-32)
  = round(31.875) + (-32)
  = 32 - 32
  = 0

# x = 0.9:
q = round(0.9 / 0.0031373) + (-32)
  = round(286.875) + (-32)
  = 287 - 32
  = 255
```

**结果：`0.1 → 0`，`0.9 → 255`**（正好用满 uint8 两端）。

---

## Step 4：反量化 x_hat = (q - zero_point) * scale

```python
# q = 0:
x_hat = (0 - (-32)) * 0.0031373 = 0.10039   # 原 0.1

# q = 255:
x_hat = (255 - (-32)) * 0.0031373 = 0.90040  # 原 0.9
```

误差 ~0.0004。至此**浮点 scale 版**完成。

---

## Step 5：定标 —— 把 scale 转成 multiplier + shift

> 目的：硬件不想做浮点乘 `* 0.0031373`，要换成整数乘 + 移位。

### 5.1 shift 怎么来（核心）

shift 不是随便选的，由两个约束锁定：

**约束 A（上限）：multiplier 不能溢出硬件位宽**

```python
# 硬件给 multiplier 16 bit → 最大 65535
multiplier = round(scale * 2^shift)  <= 65535

shift = 25 → 0.0031373 × 33554432 = 105277  ❌ 超了！
```

**约束 B（下限）：multiplier 不能太小，否则精度差**

```python
shift = 4  → 0.0031373 × 16 = 0.05  → round = 0    ← 全变 0
shift = 8  → 0.0031373 × 256 = 0.80 → round = 1    ← 1/256 误差大
```

**最优：multiplier 恰好接近位宽上限（用满分辨率）**

```python
shift = 16 → 0.0031373 × 65536  = 205.6  → round = 206
shift = 24 → 0.0031373 × 16777216 = 52648 → round = 52648  ← 更接近 65535
```

shift 越大（不溢出时）→ multiplier 越接近上限 → 精度越高。

**公式推导**（16-bit multiplier）——把"multiplier 接近位宽上限"翻译成数学：

```
目标: scale × 2^shift ≈ 2^(bits-1)      # multiplier 停在位宽一半，留防溢出余量
两边取 log2: log2(scale) + shift ≈ bits - 1
解出 shift:  shift ≈ bits - log2(scale) - 1
取整（ceil 保证整数且偏大 → multiplier 偏大 → 精度高）:
```

```python
shift = bits - ceil(log2(scale)) - 1
      = 16 - ceil(log2(0.0031373)) - 1
      = 16 - (-8) - 1     # log2(0.0031373) ≈ -8.3, ceil = -8
      = 23                # multiplier = round(0.0031373×2^23) = 26318
                         # 位宽利用率 0.3%(206) → 40%(26318)，精度更高
```

> 注1：`shift = mult_bits`（16）是工程经验默认值——大多数 scale 在 `[2^-8, 2^0]`，简单够用；严格最优按公式算。
> 注2：公式是"快速够用版"。工业级（TFLite `QuantizeMultiplier`）逐 shift 扫描选"逼近误差最小"的组合，公式只当起点。8-bit 量化误差远大于这点 shift 差异，实验用公式即可。

### 5.2 算 multiplier

```python
# 用 shift = 16（经验值）:
multiplier = round(scale * 2^16)
           = round(0.0031373 * 65536)
           = round(205.62)
           = 206

# 验证逼近:
scale_fixed = 206 / 65536 = 0.0031433   # 浮点 0.0031373
误差 = |0.0031433 - 0.0031373| = 0.000006   # 极小
```

### 5.3 定标版反量化（整数乘 + 移位替代浮点乘）

```python
# 浮点版:  x_hat = (q - zero_point) * 0.0031373
# 定标版:  x_hat = ((q - zero_point) * 206 + 2^15) >> 16
#                  └─ 乘整数        └─加半四舍五入┘  └─右移16位

# x = 0.9 → q = 255:
x_hat = ((255 - (-32)) * 206 + 32768) >> 16
      = (287 * 206 + 32768) >> 16
      = (59122 + 32768) >> 16
      = 91890 >> 16
      = 1.402   # ⚠️ 数字不凑巧，看下面代码验证
```

### 5.4 工业级做法：扫描法找最优 (multiplier, shift)

公式是"快速够用版"。工业级（TFLite `QuantizeMultiplier`）做法是**扫描所有候选 shift，选逼近误差最小的组合**：

```python
def scale_to_fixed(scale, bits, min_mult=0, max_mult=None):
    """把浮点 scale 转成 (multiplier, shift)，逼近误差最小

    参数:
        scale      : 浮点 scale（量化阶梯大小，正数）
        bits       : multiplier 的位宽（8/16/32 → 上限 255/65535/43亿），硬件定
        min_mult   : multiplier 下限，填 0 即可（防 round 成 0/1 精度崩）
        max_mult   : multiplier 上限，只有两档（由硬件是否有符号决定）:
                       无符号: 2^bits - 1      (默认，16bit → 65535)
                       有符号: 2^(bits-1) - 1  (16bit → 32767)
                     注意是 -1，2^bits 会溢出 1 位
    返回:
        (multiplier, shift)  使 scale ≈ multiplier / 2^shift
    """
    if max_mult is None:
        max_mult = (1 << bits) - 1
    best = None
    # 扫描 shift 0~2*bits：乘大数+移位的组合都试一遍，选误差最小的
    for shift in range(0, 2 * bits + 1):
        mult = round(scale * (1 << shift))
        if mult < min_mult or mult > max_mult:
            continue                       # 超出位宽，跳过（约束A）
        scale_fixed = mult / (1 << shift)
        err = abs(scale_fixed - scale) / scale   # 相对逼近误差
        if best is None or err < best[0]:
            best = (err, mult, shift)      # 记录 (误差, multiplier, shift)
    return best[1], best[2]
```

**对比公式法**：

| | 公式法 `bits-ceil(log2(scale))-1` | 扫描法 `scale_to_fixed` |
|---|---|---|
| 目标 | multiplier 接近位宽上限 | **逼近误差最小** |
| 复杂度 | O(1) 一步算出 | O(bits) 扫 2·bits 个 shift |
| 适用 | 理解/实验/玩具 | 产品/对接框架/精度敏感 |
| 边界 | 只保证"够用" | 显式处理 min/max 位宽约束 |

> 结论：两个都能用。公式 O(1) 快、够好；扫描法逐 shift 验证、最优。8-bit 量化下两者结果几乎无差（量化舍入误差远大于 shift 选择的差异），实验用公式即可，产品级用扫描法。

### 5.5 依赖链：真值 → scale → (multiplier, shift)

```
原始浮点真值 x
    ↓ 统计（min/max）
scale
    ↓ 定标转换
(multiplier, shift)
```

- **scale 一旦算出，真值就退场**——multiplier/shift 完全由 scale + bits 决定，与具体 x 无关
- **multiplier/shift 一旦算出，连 scale 都退场**——推理时只有整数 (q, zp, mult, shift)

这就是量化的本质：**浮点模型 → 纯整数模型**。离线（PC）喂 calibration 数据算好量化参数存进文件，在线（板子）只读整数参数跑纯整数路径，永远不碰原始浮点真值——这也是 T41 NNMAC / QNN / MNN 推理链路的共同结构。

## Step 6：完整代码验证（可跑）

```python
import numpy as np

# ---- 浮点 scale 版 ----
x = np.array([0.1, 0.9], dtype=np.float32)
q_min, q_max = 0, 255
x_min, x_max = np.min(x), np.max(x)

scale = (x_max - x_min) / (q_max - q_min)
zero_point = np.round(q_min - x_min / scale).astype(np.int32)
q = np.clip(np.round(x / scale) + zero_point, q_min, q_max).astype(np.uint8)
x_hat_float = (q.astype(np.float32) - zero_point) * scale
print(f"浮点版:  scale={scale:.8f} zp={zero_point} q={q} x_hat={x_hat_float}")

# ---- 定标版（multiplier + shift）----
shift = 16
multiplier = round(scale * (2 ** shift))
scale_fixed = multiplier / (2 ** shift)

# 定标反量化: 加 2^(shift-1) 做四舍五入
x_hat_fixed = ((q.astype(np.int32) - zero_point) * multiplier + (1 << (shift - 1))) >> shift
print(f"定标版:  mult={multiplier} shift={shift} scale≈{scale_fixed:.8f} x_hat={x_hat_fixed}")

print(f"\n两者差: {x_hat_float - x_hat_fixed}")
```

**预期输出**：
```
浮点版:  scale=0.00313725 zp=-32 q=[  0 255] x_hat=[0.10039 0.90040]
定标版:  mult=206 shift=16 scale≈0.00314331 x_hat=[0.10034 0.90039]

两者差: [4.8e-05  1.0e-05]   # 差 ~1e-5, 硬件却省了浮点乘
```

## 附：层间重量化（requantize）—— 定标的真正用途

> 场景：量化模型部署时，层与层之间如何传递数据？为什么"反量化不是必须的"？

### 每层有自己的 scale（层间必须转换）

```
conv1 激活域: scale_1 = 0.01
conv2 激活域: scale_2 = 0.005
```

相邻层 scale 不同 → int32 累加器的值域 ≠ 下一层期望值域 → 必须转换。

### 重量化 ≠ 反量化

```
❌ int32 → 反量化浮点 → 再量化 uint8 → 下一层   （错，多余浮点往返）
✅ int32 → (乘常数比值 + 移位) → uint8 → 下一层   （对，全整数）
```

```python
# 重量化（全整数）: 乘一个 scale 比值，用定标表示
out_u8 = (acc_i32 * multiplier + 2^(shift-1)) >> shift
#                └─ (s1·sw/s2) 的定标      └─ 四舍五入

# 反量化（浮点）: 仅最终输出 / 混合精度层才用
out_fp32 = (out_u8 - zp) * scale
```

### 每层完整链路（T41/QNN 真实形态）

```
uint8_in × int8_w     (MAC)
   ↓ int32 累加器
acc_i32 + bias_i32    (bias 预量化成 int32)
   ↓ 重量化: (acc × multiplier) >> shift    ← 每层/每通道一组
uint8_out → 下一层
```

**转换工具给的每通道一组 scale/bias/shift_count 就是这条链路**：
- `scale`：MAC 输入量化域（uint8）
- `bias`：预量化 int32，直接加累加器
- `shift_count`（multiplier/shift）：层间重量化定标参数 = `(s_in·s_w/s_out)`

### 重量化的代价：误差逐层累积

重量化本身也是量化，每层引入一次舍入误差 →
- 层越深误差累积越严重
- 量化敏感层（长尾分布）需保 fp32 或加位宽
- QAT 让模型"适应"这些层间误差

### 一句话

> 定标法只是"单次 scale 转换"的实现手段；层间连接必然要**重量化**（乘常数比值转整数域），因为每层 scale 不同。重量化是全整数操作，不是反量化。全程无浮点 = 量化模型快的核心，也是误差逐层累积的来源。
